# PUMA v4.0.1 — Post-v4.0.0 Maintenance Release

- **Release date:** 2026-11-07
- **Previous release:** v4.0.0 (tagged 2026-06-02)
- **Tag:** v4.0.1

## Overview

v4.0.1 is a patch release. It fixes the `puma share-results` stall (D40),
the Trivy gate that blocked the container image (D41), the runtime data
missing from the wheel (D42), the missing `--version` flag (D43), the
undeclared dashboard dependency (D48), the CI suites and dependency ranges
that were never tested (D49), the version lookups that fell back to
`0.0.0-unknown` (D50) and three hygiene findings (D51), and it makes
`check_rate_limit()` compatible with PyGithub >= 2.7.

The private verifier now computes the same 4-field canonical hash as the client (D23), the community validation and verification workflows were fixed (D38, D39), and the leaderboard loads submissions and shows each one's declared verification status (D46). The verifier can only check a submission that publishes raw_predictions_url; the CLI does not set that field yet, so new submissions remain self-attested until that follow-up lands. The fixed workflows have not yet been exercised by a new submission.

## Highlights

- **Runtime data in the wheel** — the wheel carries `config/profiles.yaml`,
  `config/models_catalog.yaml`, the prompt templates, the run-specs, the
  Alembic configuration and migrations, `assets/img/PUMA.png` and
  `data/jira_balanced_200.csv` under `puma/_bundled/`, used when no source
  tree is present (D42).
- **`PUMA_DATA_DIR` and `PUMA_SPECS_DIR`** — `data/` files and `specs/`
  run-specs are looked up in the named directory first, then the working
  directory, the source tree and the bundled copy.
- **`puma share-results`** — the upstream owner publishes directly to
  `pumacp/puma-community`, GitHub retries are bounded with an explicit
  timeout and a rate-limit pre-check, and transport errors surface as themed
  CLI errors (D40).
- **`puma --version`** prints `puma-cp <version>` (D43); the banner,
  `puma env`, `ProfileSnapshot.puma_version` and `puma.__version__` read the
  installed `puma-cp` version (D50).
- **CI** — `lint-and-test` runs `tests/community/` and `tests/cli/`, an
  `unpinned-deps` job tests the pyproject dependency ranges (D49), bandit
  reports MEDIUM and higher and fails on HIGH, and the docs build runs on
  every pull request.

## Install notes

```bash
pip install -U puma-cp
puma --version        # puma-cp 4.0.1
```

- `pip install puma-cp` now ships the runtime data (D42) except the TAWOS
  dataset, which users obtain from its original source and point to with
  `PUMA_DATA_DIR` or place in `./data`.
- `puma --version` prints the installed version.
- The dashboard is installable from PyPI: `matplotlib` is a declared
  dependency (D48).
- The container image ghcr.io/pumacp/puma is pushed to GHCR only by a v*
  tag push, after the Trivy gate passes; a manual run of the workflow builds
  and scans the image without pushing it.

## Known limitations

- **D44 / D45** — the H2 estimation and H1 triage inferential tests remain
  open in `docs/known_debt.md`.
- **D58** — PyPI publishing uses an API token; trusted publishing is not
  configured.
- **D59–D67** — documentation errata and backlog, deferred to the
  documentation revision.
- **D68** — `puma db migrate` with the default `--db` fails in a working
  directory without `data/`; target: next patch.
- **D69** — the container image keeps pip 24.0, whose CVEs Trivy reports
  below the HIGH gate; no released pip clears the gate; target: next patch.
- **raw_predictions_url** — not set by the CLI, so the verifier cannot check
  new submissions (see Overview).
